# Dataset directory

Raw and processed data files are never committed to git (see the root `.gitignore`). This directory
holds the dataset card, the demo dataset generator and the instructions needed to reproduce the ML
pipeline in `ml/`.

**There is no real dataset in this repository and none is downloaded.** The pipeline trains by default
on the synthetic demo dataset described below. Its results demonstrate that the pipeline works; they
say nothing about real roads, and nothing in the product or the report may present them otherwise.

## Rules

- Before using any dataset, complete a dataset card like the one below and get the licence checked
  by the team. Record the exact access date and the exact URL you downloaded from.
- Keep raw files under `data/raw/` and prepared files under `data/processed/`; both are ignored by git.
- SmartRoad's own seed data (`source: "seed"`) is never used as training data.
- Demo or synthetic data is always labelled as such (`is_demo_data: true` in the card and in the
  artifacts), and is never described as real data.

## Dataset card: SmartRoad demo incident dataset (synthetic)

| Item | Value |
|---|---|
| Dataset name | SmartRoad demo incident dataset (synthetic) |
| Publisher | SmartRoad team, generated by `data/generate_demo_dataset.py` |
| Source URL | none (generated locally) |
| Access date | none; regenerated on demand with `python data/generate_demo_dataset.py` |
| Licence | project-internal, synthetic |
| Citation requested by the publisher | none |
| Files used and sizes | `data/processed/demo_incidents.csv`, 6000 rows, about 0.5 MB, written by the generator (seed 42) |
| Number of records before cleaning | 6000 (default `--rows 6000`) |
| Number of records after cleaning | 6000: the generator never writes missing or invalid values |
| Target variable and how LOW/MEDIUM/HIGH are derived | `severity`, assigned by a documented stochastic rule: a score adds fixed contributions for higher speed limits, darkness, wet or flooded surfaces, rain or fog, highways and junctions, accident-like categories, late-night hours, weekends, rural areas and membership of a spatial cluster, plus Gaussian noise (sigma 0.6); LOW below 1.55, MEDIUM up to 2.55, HIGH above. | Class balance (counts per class) | measured on the default run (6000 rows, seed 42): LOW 2998 (50.0 %), MEDIUM 1954 (32.6 %), HIGH 1048 (17.5 %). Documented bounds checked by the tests: HIGH between 12 % and 20 %, LOW between 40 % and 62 %. |
| Features used, with type and allowed values | the ten shipped features of `docs/api.md` section 9: `hour` 0..23, `day_of_week` MON..SUN, `month` 1..12 (all three derived from `timestamp`), `light_conditions` DAYLIGHT / DARK_LIT / DARK_UNLIT, `weather` CLEAR / RAIN / FOG / OTHER, `road_surface` DRY / WET / FLOODED, `road_type` HIGHWAY / ARTERIAL / LOCAL / JUNCTION, `speed_limit` 20..120 km/h, `area_type` URBAN / RURAL, `category` (the ten SmartRoad categories). | Geographic coverage | synthetic points inside the Hyderabad bounding box 17.30..17.52 N, 78.30..78.60 E; about 35 % of the points come from eight Gaussian clusters (sigma about 165 m), the rest are uniform inside the box |
| Temporal coverage | synthetic timestamps across 24 months (2024-09-01 to 2026-08-31), local wall-clock time without a UTC offset |
| Known limitations and biases | entirely synthetic: no real road, incident or measurement is represented; the target is produced by a hand-written rule plus noise, so any metric only demonstrates that the pipeline works and says nothing about real roads; the clusters and the feature-to-severity relations were chosen by the team, not observed; feature values are drawn independently of any real road network or weather record; because the rule is additive in the features, a linear model can match or beat tree ensembles on this data, which need not hold for real data |

The generator is deterministic (`numpy.random.default_rng(42)`), takes `--rows`, `--seed` and
`--out`, prints the class balance it produced, and states on every run that the data is synthetic.

## Replacing the demo data with a real dataset

### Prepared CSV schema

`python -m training.run_pipeline --dataset <path>` accepts a CSV with these columns. Values are
trimmed and upper-cased before validation; unknown values fail with a clear error; rows with missing
required values are dropped and counted.

| Column | Type | Required | Allowed values |
|---|---|---|---|
| `timestamp` | ISO 8601 local time, e.g. `2025-03-14T18:22:00` | yes, unless `hour`, `day_of_week` and `month` are given instead | any parseable datetime (a UTC offset, if present, is ignored and the wall-clock time is kept) |
| `latitude`, `longitude` | float | yes | -90..90, -180..180 |
| `light_conditions` | text | no (derived from the hour when absent: DAYLIGHT for 6 <= hour < 18, else DARK_LIT) | DAYLIGHT, DARK_LIT, DARK_UNLIT |
| `weather` | text | yes | CLEAR, RAIN, FOG, OTHER |
| `road_surface` | text | yes | DRY, WET, FLOODED |
| `road_type` | text | yes | HIGHWAY, ARTERIAL, LOCAL, JUNCTION |
| `speed_limit` | integer km/h | yes | 20..120 |
| `area_type` | text | yes | URBAN, RURAL |
| `category` | text | yes | POTHOLE, ROAD_DAMAGE, ACCIDENT, TRAFFIC_CONGESTION, TRAFFIC_SIGNAL, STREET_LIGHT, UNSAFE_ROAD, OBSTRUCTION, WATERLOGGING, OTHER |
| `severity` | text (target) | yes; all three classes must be present | LOW, MEDIUM, HIGH |

Before training on a real CSV, fill in every `dataset_card` field in `ml/training/config.yaml`
(name, source, url, access date, licence, target definition, geographic and temporal coverage,
limitations); the pipeline refuses to run on a real dataset with an incomplete card, and the
artifacts then carry `is_demo_data: false` with the card you wrote.

### STATS19 adapter

For the UK Department for Transport "Road Safety Data" collisions table (the Phase 1 recommendation),
`ml/training/adapters/stats19.py` maps the raw columns to the schema above:

```
python -m training.run_pipeline --dataset data/raw/<stats19-collisions>.csv --adapter stats19
```

It maps `accident_severity` 1/2/3 to HIGH/MEDIUM/LOW, `light_conditions`, `weather_conditions`,
`road_surface_conditions`, `road_type` (with `junction_detail` promoting junctions), `speed_limit`
(mph to km/h), `urban_or_rural_area`, `date` + `time` to `timestamp`, `latitude`, `longitude`, and sets
`category` to ACCIDENT. Every code that does not fit the vocabulary (unknown, missing, oil, mud,
unallocated) becomes a missing value that validation drops and reports. The module docstring lists
each approximation; the adapter is unit-tested on a small made-up fixture and downloads nothing.
Record the year(s), the severity variable used (since 2016 the DfT also publishes adjusted severity
figures) and the licence (Open Government Licence v3.0 at the time of the Phase 1 check) in the card.
